# Live Script Copilot · 全栈系统交付全案

> 项目：通过 AI，帮助直播网红根据对方的语音对话，实时生成应对话术的网站
> 交付团队：全栈智造专家团（团长 + 7 位成员 · 5 阶段工作流）
> 版本：V1.0 ｜ 日期：2026-10-08

---

## 〇、诊断与结论

**诊断闸门**：通过。属标准软件交付需求（Web 网站形态），三要素齐全，非法违规/强监管/非软件/纯闲聊/人力外包五类排除场景均不适用。

| 三要素 | 结论 |
|---|---|
| 做什么系统 | AI 实时话术辅助网站（Web 优先，PC 浏览器使用） |
| 面向谁 | 直播带货主播（主）、娱乐主播（次）、MCN 机构运营（B 端付费方） |
| 核心目标 | 实时听懂对方语音，秒级生成符合主播人设、可直接照念的应对话术 |

**一句话结论**：值得做，且应尽快做，但必须 **PC Web 单端先行**、以 **「听得懂对方语音」为唯一差异化**、以 **合规预检为 P0**。

### 差异化空位（为什么是这个项目能赢）

竞品的共同弱项是**输入侧只有文本弹幕，听不懂对方口头说出的新话**：

| 类型 | 代表 | 缺口 |
|---|---|---|
| 国内直播话术工具 | 智播助手、主播宝、繁昕 | 关键词触发 + 预置话术库，答不了没预设过的问题 |
| RTC 厂商方案 | 即构直播间 AI 互动助手 | 卖给平台的 SDK，个体主播无法自助使用 |
| 海外 Sales Coach | SalesGhost / Realtime 方案 | 面向 Zoom 会议销售，无直播中文语境 |
| 数字人直播 | 火山、硅基、曦灵 | 2026 年合规风暴赛道收缩 |

本项目站位：**「听得懂对方语音 + 保留本人人设 + 内置合规预检」的实时话术教练**。

## 一、团长裁决（统一口径，消除成员间冲突）

| # | 冲突点 | 裁决 |
|---|---|---|
| C1 | 延迟指标口径：<1.5s vs ≤2.5s | **统一为：首字可见 P50 ≤1.2s / P95 ≤1.8s，完整话术 P95 ≤2.5s**（V1.5 优化目标 ≤1.5s） |

## 二、Phase 1 · 立项与定义

### 2.1 平台形态选型

七类平台打分（1~5）：**Web 网站 26 分最高**，桌面软件 23、浏览器插件 22、公众号 H5 19、App/小程序/iOS 各 13~14。

**决策：MVP = Web 网站（PC 浏览器）+ 最小 Web 后台；P1 增补 Chrome 扩展或 Tauri 桌面端；移动端本期不做。**

决定性依据：
1. 主播在固定直播间用 PC + OBS/直播伴侣长时间开播，Web 与场景重合度最高
2. Web 开发成本最低、秒级发版、仅需 ICP 备案（无商店审核）
3. App/小程序每端 60~150 人日的长期维护债，MVP 阶段不背

> ⚠️ 决定性技术发现：**macOS 上 Web 无法采集系统音频**（`getDisplayMedia` 仅支持标签页音频）。三条绕行路径：A 麦克风拾外放（MVP 零安装）／B 虚拟声卡 BlackHole 直采／C 桌面端 loopback（+15~25 人日）。**建议 Day 1 先做 200 行音频采集 demo 验证，这是唯一的"一票否决"技术点。**

### 2.2 MVP 最小闭环

```
主播开播 → 打开网页 → 授权麦克风/选虚拟声卡 → 对方说话
  → 屏幕中下方浮出 3 条话术 → 主播扫一眼念出/复制
```

**P0 九项**：实时语音采集 / 流式转写(VAD) / AI 话术生成(3 条候选) / 话术卡片 UI(主卡 32px) / 一键复制+快捷键 / 注册登录 / 人设配置 / 敏感词双层过滤 / 隐私授权。

**明确不做**（反向需求）：全自动代替主播说话（AI 嘴替）——违反《直播电商监督管理办法》与《人工智能拟人化互动服务管理暂行办法》。

### 2.3 技术选型

| 层 | 选定 | 理由 |
|---|---|---|
| 前端 | React 18 + Vite 5 + TypeScript + Zustand | 高频流式状态，React 生态最成熟；不用 Next.js（无 SEO 需求） |
| ASR | Web Speech API（MVP）→ 讯飞 RTASR（生产） | 前者零成本；后者国内稳定可达、无数据出境风险 |
| 后端 | Node 22 + Express 4 + ws 8 | 全链路 IO 密集，Node 异步模型天然匹配；前后端同构一人可维护 |
| LLM | DeepSeek deepseek-chat（OpenAI 兼容，可切任意厂商） | 中文话术质量足够、价格最低；换 base_url 即迁移 |
| 数据 | SQLite(better-sqlite3, WAL) → PostgreSQL + Prisma | MVP 单机够用；schema 按 PG 兼容写法 |
| 部署 | Nginx(HTTPS) → Node 单体 + pm2 | 日活万级内禁止上微服务 |

**延迟预算（P50/P95）**：采集+重采样 8/15 ｜ ASR 出 final 700/1000 ｜ 切片判定 80/350 ｜ LLM 首 token 550/900 ｜ 下行渲染 30/60 → **首字 ~1.1s / ~1.8s，完整话术 P95 ~2.4s**。

## 三、Phase 2 · 质量保障

**四层测试策略**：单元（Slicer 边界、single-flight、Prompt 组装、红线过滤器）/ 集成（WS 状态机、REST 鉴权、DB 归属）/ 端到端 / 非功能（性能、兼容、弱网、安全）。

**19 条 ACLN 用例**（正常 6 / 异常 13，异常占比 217%），P0 重点：三档音源切换、ASR 二级降级、WS 1/2/4 秒重连三次、genId 旧 delta 丢弃、md5 去重节流、2000 词注入 100% 拦截、静音 15s 不触发生成、水平越权拦截。

**质量门禁（任一失败不放行）**：
- P0 bug = 0；CI 冒烟 10/10
- 首字 P50 ≤1.2s / P95 ≤1.8s；完整话术 P95 ≤2.5s；REST P95 ≤500ms
- 200 并发 WS 稳定；错误率 ≤0.1%
- 已知红线词拦截 100%，盲测漏放 ≤0.1%；无高危越权/注入/XSS/密钥泄漏
- 兼容矩阵：Windows/macOS × Chrome/Edge 必测；Safari/Firefox 验证降级页；1280/1440/1920 三档分辨率

**已落地资产**：`scripts/smoke.mjs`（14 项端到端）、`scripts/check-rules.ts`（14 项合规），当前均 **全绿**。

## 四、Phase 3 · 上线发布

- **环境**：Local / CI / Test / Staging / Production 五套，数据禁止混用；密钥严禁入 Git/前端/CI 日志
- **流水线**：GitHub Actions → 类型检查 → 单元 → 集成 → **质量门禁 → 唯一制品** → Test → Staging → 人工审批 → 生产灰度（不可在服务器重新构建）
- **部署**：2C4G Ubuntu + Nginx 443 终断 + pm2（单实例、`max_memory_restart=768M`）。已给出完整 Nginx 配置（含 WebSocket Upgrade 头、`/assets/` 一年强缓存、`index.html` 不缓存）与 certbot 命令
- **发布策略**：**蓝绿双色 8787/8788 + Nginx upstream 秒级切换**（不用滚动发布，避免 WS 长连接集中断线）
- **回滚**：`RTO 10 分钟`（5 分钟完成切流）。触发条件含 P0、5xx >1% 连续 5min、延迟超阈、红线漏放任意 1 条等
- **合规风险（重点）**：ICP 备案 1~3 周为硬前置；**浏览器 Web Speech 依赖境外服务存在数据出境风险，生产必须切国内云 ASR**；生成式 AI/算法备案需法务确认；不得抓取非官方平台弹幕

## 五、Phase 4 · 运维保障

- **SLO**：可用性 99.5%/月（错误预算 216 分钟），opus 可用性 ＝ WS 连接成功率 0.4 + 生成成功率 0.4 + REST 成功率 0.2 加权，**以用户侧拨测与埋点为准，不以进程存活为准**
- **预算规则**：消耗 >50% 发版需审批；>80% 冻结非修复发布；100% 耗尽全队转稳定性专项
- **四级降级**：L0 全功能 → L1 模板话术兜底 → L2 仅转写（`FEATURE_GENERATE=off` 立即止血）→ L3 只读历史；恢复须逐级回升，每级观察 ≥5 分钟
- **四个 Runbook**：延迟飙高（区分 ASR 慢 vs LLM 慢的诊断脚本）、Key 429/供应商故障（自动熔断 + 手动切备，禁止回退境外 ASR）、SQLite 锁等待/磁盘写满、生成违规内容（30 秒内关闭生成）
- **成本护栏**：ASR 时长 >55min/主播/小时 → VAD 门控失效告警（VAD 是成本生命线，常开会让单场成本从 ¥3.6 翻到 ¥8.4）；月基线 ≈¥1100，日成本 >¥45 告警，超 100% 熔断
- **扩容触发**：200 并发（现状）→ 350+ 升 4C8G → 600+ **必须先换 PostgreSQL + Redis** → 1000+ 无状态 Node 池

## 六、Phase 5 · 运营增长

**北极星：单场有效话术采纳率 ≥40%**，四因子拆解：

```
采纳率 = 送达率 × 及时率 × 相关率 × 信任率
基线 0.92 × 0.82 × 0.60 × 0.72 = 32.6%
目标 0.95 × 0.90 × 0.72 × 0.80 = 49.2%（保守承诺 ≥40%）
```

**定价**（Web 直付微信/支付宝，费率 0.6%，**避开苹果 30% 抽成**，同样 ¥49 月毛利高 42%）：

MCN 大客户：50 席 ¥1290/月，年签 8 折。

## 九、下一步建议（按优先级）

1. **Day 1：验证音频采集链路** —— 这是唯一的"一票否决"技术点。用 200 行 demo 在 macOS + Chrome 上跑通虚拟声卡直采，确认 ASR 准确率 ≥95%，再投入完整开发
2. **同步启动 ICP 备案** —— 1~3 周，是唯一会拖垮排期的前置项
3. **接入国内云 ASR**（讯飞 RTASR） —— Provider 适配层已预留，生产不可依赖浏览器原生识别
4. **接 10 个种子主播做盲测** —— 拿到真实采纳率基线，低于 25% 立即冻结投放，转做话术质量

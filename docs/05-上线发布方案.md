# 上线发布方案

> 出品：上线发布师（Phase 3）｜参考：`release-deployment.md`

> **发布结论：有条件阻塞。** 生产发布前必须取得测试官签字的门禁结论（P0=0、CI 冒烟 10/10、首字 P95≤1.8s、完整 P95≤2.5s、REST P95≤500ms、200 并发稳定、漏放达标、兼容矩阵全通过）。任一未达标拒绝上线，**禁止"带病发布"豁免**。

## 一、五套环境

| 环境 | 数据库 | LLM/ASR | Mock 策略 | 隔离 |
|---|---|---|---|---|
| Local | 开发者独立 SQLite | 默认 Mock，可用个人沙箱 key | 全可 Mock | 禁止复制生产数据 |
| CI | Runner 临时 SQLite | 全 Mock，固定响应 | 强制 Mock | Job 结束销毁 |
| Test | 独立测试库 | Mock + 夜间供应商沙箱 | 可注入超时/断流/违规文本 | 仅合成数据 |
| Staging | 独立预发库 | 国内 ASR 测试租户 + DeepSeek 测试 Key | 仅故障演练时 Mock | 不接生产可写库 |
| Production | 独立生产 SQLite WAL | 国内云 ASR 正式 + DeepSeek 正式 Key | **禁止 Mock** | 最小权限、音频不落盘、日志脱敏 |

生产配置存 `/etc/live-script/production.env`，权限 600。`JWT_SECRET`、`LLM_API_KEY`、`XUNFEI_*` 严禁写入 Git、镜像、前端变量或 CI 日志。

## 二、CI/CD 流水线

流程：`提交/PR → 构建 → 类型/Lint/单测 → REST/WS 集成 → UI 冒烟 → 质量门禁 → 唯一制品 → Test → Staging → 人工审批 → 生产灰度`

关键 yaml 要点（`scripts/` 需提供 `typecheck`、`test:unit`、`test:integration`、`test:quality-gate`、`test:ui-smoke`、`build`、`start:ci`）：

```yaml
- name: Enforce release quality gate
  run: |
    npm run test:quality-gate -- \
      --p0-max=0 --smoke-required=10 \
      --first-token-p95-ms=1800 --suggestion-p95-ms=2500 --rest-p95-ms=500 \
      --ws-concurrency=200 --known-redline-leaks=0 --blind-leak-rate-max=0.001
```

制品同 git commit 绑定（SHA 前 7 位），Test/Staging/Production 使用**同一制品**，部署程序只允许解包，不允许在服务器重新构建。GitHub `production` Environment 必须配人工审批人。

## 三、部署架构

云服务器（Ubuntu LTS 2C4G 40G SSD）优先：支持持久 WebSocket、SQLite 本地盘、Nginx 与进程级控制。Serverless 有冷启动与连接时长限制，本期不选；静态托管暂由同机 Nginx 承接，规模增长后迁移 OSS+CDN。

**安全组只开 22/80/443**；数据库与备份目录不暴露公网。CPU 持续 >70% 或内存 >75% 升 4C8G。

### Nginx 关键配置（已含 WebSocket 升级）

```nginx
map $http_upgrade $connection_upgrade { default upgrade; "" close; }

location /ws {
    proxy_pass http://live_script;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 75s;
    proxy_buffering off;
}
location /assets/ {
    try_files $uri =404;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
location = /index.html { add_header Cache-Control "no-cache, no-store, must-revalidate"; }
```

证书：`certbot --nginx -d app.example.com --redirect --agree-tos -m ops@example.com`，启用 `certbot.timer` 自动续期。

> **不启用 Service Worker**：实时协议必须与前端版本一致，离线缓存会导致旧 WS 协议长期驻留。

## 四、灰度与回滚

**采用蓝绿发布，不用滚动发布** —— WebSocket 长连接在滚动重启时会集中断线；蓝绿可并行验证并通过 Nginx 秒级切流。

```javascript
// ecosystem.config.cjs 要点（SQLite 单写者 => 每色只 1 实例）
{ name: "live-script-blue", script: "apps/server/dist/index.js",
  exec_mode: "fork", instances: 1, autorestart: true,
  max_memory_restart: "768M", kill_timeout: 15000, wait_ready: true,
  shutdown_with_message: true }
```

灰度按 `user_id` 哈希 + 白名单分组，覆盖不同浏览器/网络/直播时段，禁止只选"理想用户"。旧色实例先停接收新会话，存量连接最多排空 10 分钟，发 `1012 Service Restart` 引导重连。

**回滚触发**：P0；5xx 连续 5min >1%；核心成功率下降 >20%；延迟连续 10min 超阈；WS 异常断开 >1%；已知红线词漏放任意 1 条或盲测 >0.1%；数据损坏/密钥泄露/重大投诉。

**RTO：10 分钟内恢复旧版本（切流目标 5 分钟）**

```bash
export PREVIOUS_VERSION="v1.0.0"; export PREVIOUS_COLOR="blue"
sudo ln -sfn "/opt/live-script/releases/${PREVIOUS_VERSION}" /opt/live-script/current
sudo ln -sfn "/etc/nginx/live-script/upstream-${PREVIOUS_COLOR}.inc" /etc/nginx/live-script/active-upstream.inc
sudo nginx -t && sudo systemctl reload nginx
curl -fsS "https://app.example.com/api/healthz"
```

数据库采用"先加后删"兼容迁移，发布前必做全量备份；默认只回滚代码不回滚结构；库损坏需 Health 负责人共同批准才可走恢复。

## 五、上线前置 Checklist

- [ ] 测试官正式门禁结论（P0=0，性能/并发/安全/兼容全达标）
- [ ] 制品带版本号与 commit，上一稳定制品可用
- [ ] **ICP 备案生效**、域名解析与 HTTPS 就绪、证书自动续期成功
- [ ] 隐私政策、用户协议、麦克风单独授权、未成年人保护、账号注销路径可访问
- [ ] 协议明确禁止无人直播/录播挂机；音频默认不落盘
- [ ] 已知 2000 词漏放 = 0，盲测 ≤0.1%
- [ ] 密钥未进 Git/前端/日志；生产与非生产完全隔离
- [ ] 监控覆盖 5xx、延迟、WS 在线与断连、ASR/LLM 错误、过滤命中、磁盘与 SQLite 锁等待
- [ ] 蓝绿切换、WS 排空、Nginx 回切、发布前备份、核心冒烟已演练

## 六、合规与审核风险（本项目强监管点）

1. **ICP 备案**：大陆节点通常 1~3 周，是硬前置，纳入关键路径，**禁止备案未完成先解析运营**
2. **数据出境风险（最高优先级）**：浏览器 Web Speech API 可能把音频交由境外浏览器厂商处理，路径与保存策略不可控 → **生产必须切换境内部署的官方签约云 ASR**，明确处理地域、保存期限与删除机制；确需跨境须经法务评估
3. **生成式 AI / 算法备案**：面向境内公众提供生成内容，可能涉及算法备案与内容标识要求，上线前由法务确认，保留供应商合规材料
4. **直播平台规则**：仅使用官方开放接口，**不抓取非官方弹幕**；逐平台核对辅助工具与营销话术规则
5. **不当使用连带风险**：用户无人直播、录播挂机或生成违法营销内容可能形成连带责任，须以协议、风控、封禁、审计与投诉机制治理

## 七、发布日 Runbook

| 阶段 | 观察窗 | 继续条件 | 回滚决策 |
|---|---|---|---|
| 1% | 2h | 五项冒烟通过、延迟达标、无漏放/P0 | 任一硬门禁失败立即回滚 |
| 10% | 4h | 5xx<0.5%、WS 异常断开<1%、供应商错误率<2% | 指标恶化或投诉异常则暂停 |
| 50% | 12h | 核心成功率跌幅<5%、资源<70% | 连续两周期超阈值回滚 |
| 100% | 24h | 全指标稳定、无安全合规事件 | 命中全局触发条件立即切旧色 |

发布后 24h 轮值：T+30min 核验错误率与延迟；T+2h 检查断连、过滤命中与投诉；T+12h 检查磁盘、SQLite 锁等待、供应商额度；T+24h 决定停止旧颜色，继续观察至 T+72h 并复盘。

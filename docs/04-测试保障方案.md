# 测试保障方案

> 出品：质量测试官（Phase 2）｜参考：`qa-testing.md`

## 一、范围与阻塞项

**范围**：Web MVP，覆盖 F-01~F-09、核心页面 `/login`、`/persona`、`/live`、`/history`、`/settings` 及 REST/WS/SQLite 链路。移动端 App、小程序、TTS、开放 API 不在本期。

**测试阻塞项 → 团长已裁决**：

| 阻塞项 | 裁决 |
|---|---|
| 风格枚举 3 种 vs 5 种 | 统一 5 种，MVP 预设 3 套 |
| Windows 快捷键映射 | `⌘K` ↔ `Ctrl+K` 双判定 |
| 违规漏出率 0 vs ≤0.1% | 已知 2000 词漏放 = 0；盲测漏放 ≤0.1% |
| 音频留存默认值 | 默认不留存，仅转写文本；日志脱敏 |

## 二、四层测试策略

| 层次 | 策略要点 |
|---|---|
| 单元 | Slicer 边界（350ms/2500ms/minChars）、single-flight（1200ms 节流 + 3000ms 去重）、Prompt 拼装、红线过滤器 |
| 集成 | WS 消息状态机、REST 鉴权与统一响应、DB 事务/归属/分页 |
| 端到端 | 注册 → 授权 → 选音源 → 转写 → 生成三条 → 复制/反馈 → 结束会话（含全部异常降级） |
| 非功能 | 性能、兼容、弱网、安全 |

节奏：提测冒烟 → P0 全量功能 → 兼容/性能/安全 → 修复回归 → UAT。**测试期被压缩须书面披露风险，不得默认放行。**

## 五、专项测试

1. **实时性**：埋点用单调时钟记 `audio_first → asr_first → suggestion_first → suggestion_done`，预热后采 ≥1000 轮，输出 P50/P95/P99；服务端与浏览器用 traceId 对齐
2. **200 并发 WS**：k6/Artillery 建 200 独立会话，15s 心跳持续发 `asr_text/control`，混入 10% 取消/重生成，持续 30 分钟；Mock Provider 隔离本系统能力后再用小流量真实 Provider 复核
3. **弱网**：DevTools + Toxiproxy 注入 100~500ms 抖动、5%/10% 丢包、2s/30s 断网，验证提示、重连、幂等、旧消息丢弃
4. **ASR 评测**：100 句双人校对集（安静普通话 40 / 轻 BGM 20 / 回声 20 / 直播术语数字 10 / 轻口音 10），中文 CER 计分；安静 ≥92%，虚拟声卡 ≥97%
5. **AI 盲评**：≥200 输入覆盖 5 类意图 × 各风格，3 名评委隐藏模型版本评「可直接念/相关性/人设一致/流畅度/风险」；可直接念 ≥60%，人设一致 ≥85%

## 六、CI 冒烟清单（10 条，必须 10/10）

1 注册登录 + JWT 刷新 + A 访问 B 被拒 ｜ 2 Persona CRUD 与 Prompt 拼装 ｜ 3 未授权零音频上行 ｜ 4 Web Speech 失败自动降级 ｜ 5 WS hello/心跳 ｜ 6 ASR final 触发 3 条建议 ｜ 7 红线拦截与安全替代 ｜ 8 genId 旧消息丢弃 ｜ 9 断线重连与去重 ｜ 10 复制/暂停/重生成快捷键

单元用 Vitest，REST/WS 用 Supertest/ws，UI 用 Playwright。

## 七、质量门禁（任一失败不放行）

- **P0 bug = 0**；P1 全部修复（例外需书面列出责任人、影响、规避方案、修复日期）
- 核心链路通过率 100%；全量执行率 100%、通过率 ≥95%；**CI 冒烟 10/10**
- 首字 P50 ≤1.2s / P95 ≤1.8s；完整话术 P95 ≤2.5s；REST P95 ≤500ms
- 200 并发 WS 稳定；错误率 ≤0.1%；JS 错误会话占比 ≤0.1%
- 已知 2000 词拦截率 100%，盲测漏放 ≤0.1%；无高危越权/注入/XSS/密钥泄漏
- 兼容矩阵全部执行；隐私授权、HTTPS、音频不留存验证通过

**缺陷定义**：P0＝崩溃、数据丢失/泄漏、核心闭环阻断、违规内容放出；P1＝主要功能错误或显著性能/兼容问题；P2＝非核心异常且有绕行方案。

# 运维保障方案

> 出品：运维守护师（Phase 4）｜参考：`ops-monitoring.md`
> 本产品为**强实时**产品，延迟超标即产品失效，故监控重心在业务质量层与第三方依赖层。

## 一、部署架构与 SPOF

```
用户（主播 PC Chrome/Edge） --HTTPS/WSS--> [Nginx 443 终断]
   upstream copilot { 127.0.0.1:8787(蓝) / 8788(绿) backup }
   !! SPOF-1: 单台 2C4G 无备机（依赖云快照重建 ~30min）
        |
   [Node 22 单体 · pm2]
     REST P95<=500ms ｜ WS 心跳15s/45s超时/genId/single-flight
     能力开关 /etc/live-script/flags.json（热加载，可秒级关闭生成）
     pino JSON -> logrotate 100M x 14
        |
   +------------+------------+------------+
[SQLite WAL]  [国内云 ASR]  [LLM DeepSeek]
!! SPOF-2     !! SPOF-3     !! SPOF-4(配额/429)
单写者不可横向  备: 阿里云ASR  备: 备用 Provider
禁用浏览器 Web Speech（数据出境红线）
备份: 每日 03:00 全量 -> 本机7天 + 异地30天
```

资源月度基线 ≈ ¥1100（ASR ¥600~900 为最大项、LLM ¥300~500、主机 ¥145、其他），护栏线 ¥1400。

## 二、SLO 与错误预算

| SLI | 口径 | SLO |
|---|---|---|
| WS 连接成功率 | 握手成功/发起（排除客户端网络错误 1006） | ≥99.5%/月 |
| 生成成功率 | genId 完成且返回 ≥1 条/触发生成（排除用户主动 abort） | ≥99.0%/月 |
| REST 成功率 | 非 5xx/总请求 | ≥99.5%/月 |
| 首字可见 / 完整话术 | 客户端埋点上报 | P50≤1.2s·P95≤1.8s / P95≤2.5s |
| 月度可用性 | 以上三项加权 0.4/0.4/0.2 | **≥99.5%** |

**错误预算 216 分钟/月**（滚动 28 天）：>50% 发版需审批；>80% 冻结非修复发布；100% 耗尽全队转稳定性专项。**以用户侧拨测 + 埋点为准，进程活着但 LLM 全 429 即判定不可用。**

## 三、监控指标与告警阈值

### 基础设施层（30s 采集）

| 指标 | 阈值 | 级别 |
|---|---|---|
| CPU / 内存 | >80% 持续 10min；>85% 持续 10min（>700M 预警） | P2/P1 |
| 磁盘使用 | >85% 告警；>92% P1；**>95% P0 自动清理归档** | P1/P0 |
| 句柄数 | >80% 上限持续 5min | P2 |
| **SQLite 锁等待** | busy 等待 >50ms 写次数 >10 次/5min；SQLITE_BUSY >5 次/5min | P1 |
| WAL 文件 | >100MB 持续 30min（checkpoint 未生效） | P2 |

### 应用服务层

REST P95>500ms / P99>1000ms 持续 10min（P1）｜ WS 在线会话 3min 内突降 >50% 或 >180（P1）｜ 非客户端主动 close 占比 >5% 持续 5min（P1）｜ pm2 10min 内重启 ≥3 次（**P0**）｜ JS 错误会话占比 >2% 持续 10min（P1）｜ 证书到期 30/7/1 天分级（P2/P1/P0）

### 业务质量层（核心）

| 指标 | 阈值 | 级别 |
|---|---|---|
| **采纳率（copy 率）· 北极星** | 日活 <25% 持续 2h；环比跌 >30% | P1（静默故障） |
| 首字 P50/P95 | >1.2s 或 >1.8s 持续 10min | P1 |
| 完整话术 P95 | >2.5s 持续 10min | P1 |
| ASR interim 首现 | P95>600ms 持续 10min；>1500ms 持续 2min | P1 |
| ASR 失败率 | >3% 持续 5min；**>20% 持续 2min 触发熔断** | P1/P0 |
| LLM 首 token | P50>800ms / P95>1200ms 持续 10min | P1 |
| LLM 429/超时 | >5% 持续 5min；>20% 持续 1min 切备 Provider | P1/P0 |
| abort 率 | >40% 持续 30min（产物不受用 → 反哺研发） | P2 |
| **违规漏放** | 单次命中即 **P0**（合规红线，非统计指标） | P0 |

### 成本/配额层

单主播单场 token >8000（提示 prompt 膨胀）｜ **ASR 时长 >55min/主播/小时 → VAD 门控失效告警（VAD 是成本生命线，常开会让单场成本 ¥3.6→¥8.4）**｜ 日成本 >¥40 提醒、>¥45 P1｜ DeepSeek 余额 <3 天用量 P1，<1 天 P0｜ 讯飞额度 <20% P1、<5% P0｜ 单 IP 生成 >300 次/小时判定刷量自动限流

## 四、告警分级与防风暴

| 级别 | 定义 | 渠道 | 响应 |
|---|---|---|---|
| P0 | 服务不可用/违规漏放/数据风险/反复重启 | 电话+短信群呼至认领 | 15min 内响应启动应急 |
| P1 | 核心降级、延迟超标、依赖故障 | IM @值班；夜间短信 | 工作时间 30min |
| P2 | 资源偏高、证书临期、成本提醒 | 邮件+日报 | 当日/次日 |

防风暴：按 `service+metric+host` 指纹 5min 内同指纹只发 1 条；ASR 熔断后抑制下游"延迟超标/采纳率下降"告警 30min，只留根因；发布期间静默 15min（P0 不静默）；**月告警复盘，误报率 >30% 的规则必须调阈值或下线**。

## 五、应急预案 Runbook

### 场景 A：端到端延迟突然飙高

```bash
/opt/live-script/ops/diag-latency.sh   # 输出 asr_interim / llm_first_token / render 三段
# 判定：ASR 慢 -> asr_interim P95>600ms；LLM 慢 -> llm_first_token P95>1200ms；两者正常但慢 -> 前端/网络
```

止血：LLM 慢 → 切备 Provider；ASR 慢 → 切国内备选；两者均慢 → 降级 L1（模板兜底）；本次发布引起 → **立即 Nginx 切回另一色（RTO 10min），先回滚再查因**。

### 场景 B：Key 429 / 额度耗尽 / ASR 供应商故障

```bash
sudo -u copilot python3 /opt/live-script/ops/flagctl.py set llm_provider backup
sudo -u copilot python3 /opt/live-script/ops/flagctl.py set asr_provider backup
pm2 reload copilot && sleep 3 && /opt/live-script/ops/diag-latency.sh
```

Key 耗尽 → 走备用 Key 槽位并同步充值；ASR 主路故障 → 切国内备选，**绝不允许回退到浏览器 Web Speech API（数据出境红线）**。

### 场景 C：SQLite 锁等待 / 磁盘写满

```bash
sqlite3 /data/copilot.db "PRAGMA wal_checkpoint(TRUNCATE); PRAGMA busy_timeout;"
lsof /data/copilot.db* | head -20
logrotate -f /etc/logrotate.d/copilot
flagctl.py set persist_history false     # 临时关闭非关键写
```

根因修复：`busy_timeout` 提至 5000ms；写操作合并 1s 批量事务；磁盘扩容并加 80% 水位告警。

### 场景 D：生成违规内容被投诉（30 秒止血）

```bash
sudo -u copilot python3 /opt/live-script/ops/flagctl.py set generate_enabled false
sudo -u copilot python3 /opt/live-script/ops/flagctl.py set degradation_level L2
pm2 reload copilot
curl -s http://127.0.0.1:8787/healthz | python3 -m json.tool    # 校验开关生效
grep '"evt":"gen_audit"' /var/log/copilot/audit.log | grep "<traceId>" > /tmp/incident_$(date +%F).json
```

Nginx 硬兜底：开关失效时把生成相关接口改 `return 503`。定位后确认是规则库缺失还是模型越狱，24h 内回归漏放率门禁。

## 六、降级与熔断矩阵

| 级别 | 触发 | 表现 |
|---|---|---|
| L0 全功能 | 默认 | 实时转写 + AI 生成 3 条 |
| L1 模板兜底 | LLM P95>1200ms 持续 10min / 429>20% / 额度耗尽 | 出模板卡片，标注"模板推荐" |
| L2 仅转写 | LLM 双 Provider 全不可用 >5min；**合规事件手动关闭** | 只出大字号字幕，提示"AI 建议暂时不可用" |
| L3 只读历史 | SQLite 持续 BUSY >5min / DB 损坏 / 磁盘 >95% | 只读历史，禁止新建会话 |

**熔断参数**：滑窗 20 样本；失败率 ≥50% 或连续 5 次超时（LLM>5s、ASR>3s）→ open 30s → half-open 放行 5 请求，成功率 ≥80% 闭合。**恢复必须逐级回升，每级观察 ≥5min，禁止一步跳回 L0。**

## 七、容量规划与成本优化

| 阶段 | 触发 | 动作 |
|---|---|---|
| 现状 200 并发 | WS 在线 >180 预警，>190 排队 | 保持单实例 |
| 350+ | CPU>80% 持续 3 天 | 升 4C8G，pm2 cluster=2 |
| 600+ | 单写者瓶颈凸显 | **必须先换 PostgreSQL + Redis**（架构约束，已上报团长） |
| 1000+ | — | 无状态 Node 池 + PG 主从 + Redis 哨兵 + 网关独立限流 |

成本优化：①VAD 门控生命线（ASR 时长 >55min/h 告警）②模板命中率 ≥30% ③prompt 压缩 + max_tokens 上限，单场 token 6000→4000（-33%）④single-flight 削减重复调用 ⑤静态资源 CDN 降 70% 回源 ⑥staging 非工作时段关机

## 八、日志、审计与备份

- 结构化字段：`ts, level, svc, env, traceId, sessionId, userIdHash(sha256前8位), evt, durMs, ok, errCode, provider, rulesVersion`；**手机号只存 `138****8000`，Key/token 一律不落日志，音频不落盘**
- 审计日志 `gen_audit`（traceId + 输入摘要 hash + 输出全文 + rulesVersion + 命中规则）**留存 ≥6 个月**
- 应用日志可检索 ≥14 天，归档 ≥90 天；磁盘 >85% 联动提前清理归档
- 备份：`scripts/backup_db.py`（`VACUUM INTO` 一致性快照 + sha256 校验 + 异地投递 + 7 天轮转）

```bash
0 3 * * * copilot /usr/bin/python3 /opt/live-script/current/scripts/backup_db.py >> /var/log/copilot/backup.log 2>&1
0 9 * * * copilot /usr/bin/python3 /opt/live-script/ops/verify_backup.py >> /var/log/copilot/backup.log 2>&1
```

**RTO ≤2h，RPO ≤5min**；每季度至少 1 次从备份恢复到 staging 的演练，**未演练过的备份视为不存在**。

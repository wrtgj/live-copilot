# 需求与平台选型报告

> 出品：选品洞察师（Phase 1）｜参考：`requirement-analysis.md`、`platform-selection.md`

## 一、需求概述

| 要素 | 结论 |
|---|---|
| 业务目标 | 让主播"不冷场、不失语、不违规"，把临场反应从个人天赋变成可规模化能力 |
| 核心流程 | 音频采集 → VAD 门控 → 流式 ASR → 意图/情绪判定 → 人设化话术生成 → 合规预检 → 主播速读 → 上屏/复制 |
| 场景优先级 | **连麦 PK > 粉丝连麦 > 黑粉应对 > 商务连麦 > 弹幕互动** |
| 关键约束 | 预算上限、期望上线时间、主体资质、域名备案情况待用户确认（影响成本红线与排期） |

## 二、用户画像与场景

| 角色 | 状态 | 痛点 | 爽点 |
|---|---|---|---|
| 带货主播（PC + OBS） | 双眼盯镜头与商品，双手操作上下架 | 被问到没准备的参数就卡壳；注意力在弹幕/数据/提词器间碎裂 | 对方话音刚落，屏幕上已有 3 条可直接念的回应 |
| 娱乐主播（多为手机） | 站着走动，情绪驱动 | PK 被怼反应慢一拍就掉粉 | 秒回金句，节奏压制对手 |
| MCN 运营 | 管 10~50 主播 | 新人孵化慢、话术培训靠扒录像、无法量化 | 统一人设下发 + 采纳率看板 |

前三类场景是"不可预演、必须临场"的高焦虑时刻，价值最高；弹幕互动已被关键词机器人覆盖，差异化最弱。

## 四、竞品与差异化

详见全案。核心结论：竞品共同弱项是**听不懂对方口头说出的新话**，RTC 方案只卖 SDK 给平台，海外 Sales Coach 无中文直播语境，数字人赛道因合规收缩。

本项目站位：**听得懂对方语音 + 保留本人人设 + 内置合规预检**，自助交付给个体主播与 MCN。

## 五、平台形态选型

### 5.1 决定性技术发现

> **Web 端在 macOS 上无法采集系统音频/对方语音**。`getUserMedia` 只能拿麦克风，`getDisplayMedia({audio:true})` 在 macOS 仅支持共享标签页音频，而主播的连麦声音来自 OBS/直播伴侣（非浏览器）。

三条绕行路径：

| 路径 | 可行性 | 代价 |
|---|---|---|
| A 麦克风拾外放声 | MVP 可用，零安装 | 回声 + BGM，ASR 准确率降 5~10pt |
| B 虚拟声卡（BlackHole/Voicemeeter） | 音质最优 | 主播需手动配置，有转化流失 |
| C 桌面端 loopback（Tauri/Electron） | 体验最优，可置顶悬浮窗 | 开发成本 +15~25 人日 |

### 5.2 打分矩阵（合计）

Web 网站 **26** ｜ 桌面软件 23 ｜ 浏览器插件 22 ｜ 公众号 H5 19 ｜ 跨端 App 14 ｜ iOS 原生 13 ｜ 小程序 13

**结论：MVP = Web 网站 + 最小 Web 后台；P1 增补 Chrome 扩展或 Tauri 桌面端；移动端本期不做。**

切换条件：若验证后虚拟声卡配置流失率 >50%，或付费主播中 PC 占比 >80%，切换为「Tauri 桌面端（主）+ Web 控制台」；移动端仅当娱乐主播占比 >50% 时启动（App，非小程序——小程序无法后台常驻采音，直接出局）。

## 六、MVP 范围

- **P0（约 30~40 人日）**：账号登录、音频采集页、VAD + 流式 ASR、五类意图触发、人设配置、话术生成 3 条候选、违禁词过滤与重生成、复制/上屏、音频不留存开关
- **P1**：情绪标签、商品卡 RAG、Chrome 扩展或 Tauri 桌面端、最小后台（场次/采纳率/高频问题）、金句库
- **P2**：直播复盘报告、来源标注、多主播席位、方言模型

MVP 功能 9 项，未超 15 项红线。

## 七、可行性评估

| 维度 | 结论 | 依据 |
|---|---|---|
| 技术 | 可行（**中风险**） | ASR/LLM/VAD 均有成熟第三方，唯一攻关点是音频采集链路（macOS 限制最严） |
| 成本 | 可行（低~中） | 开发 30~40 人日；运行 4h/场 VAD 门控下 **¥3.6/场**；100 日活主播 ≈ ¥1.1 万/月。**若不做 VAD，单场成本翻至 ¥8.4，VAD 是成本生命线** |
| 时间 | 可行（中） | 总计 6~9 周，**ICP 备案 1~3 周是唯一会拖垮排期的前置项** |
| 合规 | 可行（**中高风险**） | ICP 备案、隐私政策 + 音频不留存、协议明确禁止无人直播、违禁词库属 P0、**不抓非官方弹幕接口** |

**延迟验算**：原始链路合计 1280ms 首句 / 1630ms 完整 > 1.5s 目标。压缩三招：①ASR 中间结果提前预生成 ②小模型 + prompt 压到 300 token（首 token →300ms）③输出限 30 字流式上屏 → 可压至 ≈1.3~1.4s。

**风险清单（按严重度）**：①音频采集边界（高，决定性）②延迟超标即产品失效（高）③ASR 在 BGM/方言/回声下掉到 90% 以下（中高）④生成违规话术致主播被罚（中高）⑤平台话术循环检测误伤（中）⑥ASR 成本失控（中）⑦C 端付费意愿弱（中）

## 八、关键指标基线

| 指标 | 目标 |
|---|---|
| 延迟 | 首句可见 P95 ≤800ms（优化后）；完整话术 P95 ≤1.5s（MVP）；P99 ≤2.5s |
| ASR 准确率 | 普通话含轻度 BGM/回声 ≥95%（CER ≤5%）；虚拟声卡直采 ≥97%；方言 P2 ≥85% |
| 生成质量 | 人工盲评"可直接念"≥60%；人设一致率 ≥85%；**违规词漏出率 0** |
| **北极星（首周试用）** | **单场有效话术采纳率 ≥40%**（采纳＝复制或明显口播） |
| 辅助指标 | 7 日回访开播率 ≥30%、单主播周均开播 ≥3 场、平均每场采纳 ≥15 条 |

## 九、交接给下游

端组合＝Web 网站（C 端主播）+ Web 后台（B 端运营）；技术栈约束＝实时音频链路 + 流式 ASR + 流式 LLM，前端需常驻浮层；发布通道＝ICP 备案 + HTTPS 域名，无商店审核；合规前置＝隐私政策 + 违禁词库 + 免责条款。

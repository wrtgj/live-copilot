# 技术研发方案

> 出品：全栈研发师（Phase 1）｜参考：`tech-stack-architecture.md`
> 本方案已落地为可运行代码，见仓库根目录 `apps/`、`scripts/`

## 一、总体架构与延迟预算

```
[主播 PC · Chrome/Edge]
  (1) 音源: getUserMedia(麦克风) / getDisplayMedia(标签页音频) / 虚拟声卡      ~0ms
        |
  (2) 浏览器 Web Speech API 出字（interim 250~500ms / final 700~1000ms）
        |     仅文本经 WS 上行 asr_text                                    20~40ms
        +--进阶-- PCM 16kHz/Int16 经 WS 上行 -> 服务端转发云 ASR            300~700ms
  (3) Slicer 语义切片（asr_final / tail_word / 350ms 静音尾 / 2.5s 超时）    0~300ms
  (4) Context 组装：滚动摘要(≤120字) + 最近 6 句                            <10ms
  (5) 模板缓存命中（目标 25~35%）-> 0 延迟直接返回
  (6) LLM 流式生成（首 token 400~800ms，全文 +600~900ms）
  (7) WS 下行 suggestion.delta 逐 token 推送                                10~30ms
  (8) 前端增量渲染（requestAnimationFrame）                                <16ms/帧
--------------------------------------------------------------------------------
端到端首字可见  P50 ~1.1s / P95 ~1.8s ｜ 完整话术 P95 ~2.4s
```

## 二、选型总表

| 层 | 选定 | 理由 |
|---|---|---|
| 前端 | React 18 + Vite 5 + TypeScript + Zustand + 原生 CSS | 高频流式状态；不引 antd 以控制首屏体积 |
| 状态 | Zustand 5 | 单文件 store，比 Redux 轻 |
| 音频 | getUserMedia / getDisplayMedia + AudioWorklet 重采样 16kHz | 浏览器原生零依赖 |
| ASR | Web Speech API（MVP，零成本）→ 讯飞 RTASR（生产，密钥留服务端） | Provider 适配层 Day 1 就位 |
| 后端 | Node 22 + Express 4 + ws 8 | IO 密集 + 前后端同构，一人可全栈维护 |
| LLM | DeepSeek deepseek-chat（OpenAI 兼容协议），可切任意厂商 | 便宜、换 base_url 即迁移 |
| 数据 | SQLite(better-sqlite3, WAL) → PostgreSQL + Prisma | MVP <100 主播够用 |
| 部署 | Nginx(HTTPS) → Node 单体 + pm2 | 禁止 MVP 上微服务 |

> **MVP 与进阶边界**：MVP 必须零成本可跑（浏览器原生 ASR + 可插拔 LLM key）；云端 ASR、Electron/Tauri 桌面端属进阶。

## 三、WS 协议

```ts
export type C2S =
  | { t: "hello"; token: string; personaId: number; sessionId?: number }
  | { t: "asr_text"; id: string; text: string; isFinal: boolean; speaker: Speaker }
  | { t: "audio"; seq: number; pcm: string; sampleRate: number }
  | { t: "control"; op: "start" | "stop" | "ping" | "cancel" | "regenerate" }
  | { t: "feedback"; suggestionId: number; action: "copy" | "adopt" | "skip" | "dislike"; text?: string };

export type S2C =
  | { t: "status"; state: "ready"|"listening"|"generating"|"degraded"|"blocked";
      asrProvider: string; llmProvider: string; sessionId: number; generateEnabled: boolean }
  | { t: "transcript"; id: string; speaker: Speaker; text: string; isFinal: boolean; at: number }
  | { t: "suggestion"; genId: number; index: number; phase: "start"|"delta"|"done"|"abort";
      text?: string; source: "llm"|"template"; latencyFirstTokenMs?: number; blocked?: boolean; reason?: string }
  | { t: "usage"; promptTokens: number; completionTokens: number; costMicros: number }
  | { t: "error"; code: string; message: string; retryable: boolean }
  | { t: "pong"; ts: number };
```

约定：心跳 15s，服务端 45s 无心跳断连；前端指数退避重连 1s/2s/4s，上限 3 次；**genId 单调递增，客户端只渲染最新 genId 的 delta，旧包直接丢弃**（解决取消竞态）。

## 四、核心算法策略

### 4.1 语义切片 Slicer

三重触发任一满足即 flush：`asr_final`（强切信号，最可靠）/ `tail_word`（语气词收尾）/ `timeout`（2.5s 上限）。推荐参数 `silenceMs=350, maxPendingMs=2500, minChars=4`。

> **落地修正**：原方案 `minChars=8` 在实测中把「发货要等多久呢」这类 7 字短句挡掉了。直播场景短提问极高频（"包邮吗""便宜点呗"），已改为 **4**，靠节流/去重兜住重复调用成本。

### 4.2 增量摘要滚动上下文

环形缓冲保留最近 12 条 utterance，Prompt 只取最近 6 条；每 10 条触发一次异步滚动摘要压缩为 ≤120 字；会话超过 20 轮自动截断；上下文 ≥1500 tokens 时先裁最旧两句。

### 4.3 并发、去重与取消（single-flight）

- `MIN_INTERVAL_MS=1200` 节流
- md5 归一化文本 3 秒内去重（去标点与语气词后计算）
- 新请求到来时 `AbortController` 取消在途生成
- 前端 `control.cancel` 可主动 abort

### 4.4 Prompt 结构

```
你是一名资深直播运营专家，任务是为主播生成「下一句立刻可以说出口」的话术。
【人设】{name}｜场景：{scene}｜风格：{style}
【行业类目】{category}   【口播节奏】{tone}
【输出要求】3 条候选，行首标注 1) 2) 3)，每条 20~40 字，口语短句可直接照念，
          不加引号/解释/表情/括号说明；三条分别偏「接话」「化解」「推进」。
【绝对禁止】1. 禁词名单  2. 虚假宣传（疗效/收益/极限词）  3. 诱导打赏
           4. 低俗辱骂、涉政涉黄涉赌  5. 捏造参数/优惠/库存/发货时间
```

参数：`temperature=0.8, max_tokens=120, top_p=0.95`（短输出是降延迟第一杠杆）。

## 七、多级降级

| 级别 | 触发 | 表现 |
|---|---|---|
| L0 全功能 | 默认 | 实时转写 + AI 生成 3 条 |
| L1 模板兜底 | LLM 失败/超时/配额耗尽 | 按意图模板返回话术，标注「模板」 |
| L2 仅转写 | `FEATURE_GENERATE=off` | 只出字幕，不出卡片（合规紧急止血开关） |
| L3 只读历史 | DB 故障 | 无法新建会话 |

## 八、延迟优化路线

V1（Web Speech + 流式 + 端点切片）→ 1.2s ｜ V1.5（WS 预连接预热、prompt 压缩 ≤400 tokens、模板缓存 100+ 意图、max_tokens 80）→ 1.0s ｜ V2（半句投机生成 + 浏览器端 Silero VAD）→ 0.8s ｜ V3（本地小模型出首句 + 云端精修）→ ≤0.6s。

**横向扩展**：MVP 单机 200 并发；超过后 WS 网关与 LLM 编排拆无状态多实例，SQLite 迁 PostgreSQL，模板缓存迁 Redis。**当前不引入（过度设计）**。

## 九、技术风险 Top3

| # | 风险 | 触发 | 预案 |
|---|---|---|---|
| R1 | Web Speech 国内不可达（依赖 Google 服务） | 5s 无 interim 或 network 错误连续 2 次 | 切服务端云 ASR；仍失败则降级手动输入；生产不应依赖该路 |
| R2 | LLM 延迟抖动/429 | 首 token >1.5s 连续 3 次或 429 | 多 Provider 切换 + 模板缓存兜底 + 状态栏提示 |
| R3 | 音频采集失败 | 无 audio track 或电平 <-50dB 持续 3s | 三步自检向导（共享标签页 → 虚拟声卡 → 麦克风）+ 电平可视化 |
